# Правила документації

## §1 Де що живе
| Що | Куди |
|---|---|
| Довговічний документ | `docs/<category>/` + рядок у найближчому README **в тому ж коміті** |
| Поточний стан (snapshot, не історія) | `.claude/memory/status.md` |
| Рішення | `.claude/memory/decisions.md` (`### YYYY-MM-DD — <тема>`, з варіантами, що програли) |
| Сирий вихід воркерів, чернетки | `.handoff/` (gitignored) або scratchpad сесії — ніколи в репо |

## §2 Іменування
- Point-in-time документи: `YYYY-MM-DD-slug.md`; living-документи без дати; впорядковані колекції `NN-slug.md`.
- Назви планів — словами, lowercase kebab, ≥2 змістовних слова, без вигаданих кодів. H1 обов'язковий, теж ≥2 змістовних слова.
- Переміщення — тільки `git mv`.

## §2.1 Преамбула плану і юніти
Кожен план починається з рядків `Status: draft | active | done | superseded → <path>` та
`ID namespace: none`. Юніти — `### N.M \`word-name\` — <state>`; стан — суфікс заголовка.
Тіло: `## 0 Why/scope` → `## Baseline (verified <date>)` → `## Units` → `## Order and start conditions` → `## Risks` → `## Decisions / gates / open questions`.

## §3 Один власник на факт
Усюди інде — посилання, не копія. Скопіював більше 2 абзаців — зупинись і постав лінк.

## §4 Посилання
Шляхи від кореня репо в бектиках або відносні md-лінки. Ніколи не цитуй номер рядка іншого документа — цитуй секцію: `path` §«Назва». Код цитуй орієнтиром (`process.py (def summarize)`). Жодних абсолютних шляхів машини.

## §5 Roadmap і живий курсор
`docs/plans/roadmap/` володіє життєвим циклом юнітів (draft → design-done/Gate P → code-done/merged → superseded). `status.md` тримає лише активний фронт, блокери й наступну дію; розбіжність — roadmap правий. Текст циклу пишеться в голосі «вже змерджено», ніколи «PR відкритий».

## §6 Гейти (⛔)
Відкритий гейт — рядок у плані чи roadmap:
`⛔ \`gate-name\`: невідомо X; БЛОКУЄ <unit>; ЗАКРИЄ <evidence>; відкрито <date>`.
Закритий переписується як `\`gate-name\` — ЗАКРИТО <date> (хто, що вибрано, чому програли інші)` у **кожній** копії. Сесія, що доходить до роботи за відкритим гейтом, зупиняється і повертає питання.

## §7 Завершення
Виконаний план видаляється `git rm` у тому ж PR; провенанс — git history. Архівуються лише специфікації (`docs/specs/archive/` з банером done/superseded). Заморожені записи не переписуються.
